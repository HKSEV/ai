## 검증한 흐름

- OAuth state·쿠키·일회성 nonce, 카카오 인가 코드→토큰→서버 사용자 ID 확인 HTTP 규격, 첫 가입·기존 닉네임 유지·닉네임 충돌 재시도·로그아웃·세션 만료.
- 닉네임·취향·가격대 저장 후 다른 서버 세션에서 재조회, 중복/입력값 검증, 주소 CRUD·기본 주소 단일 유지와 타인 접근 차단.
- 서비스 사용 후기와 식당 리뷰 DB 저장·목록·유형 필터·정렬·페이지·상세·본인 수정/삭제. 타인 변경 및 인증 상태 위조 차단.
- 영수증 본인 조회, 게시글 연결 사진만 커뮤니티에 표시, 잘못된 파일 형식 차단, 연결 해제 시 파일 삭제. 첨부만으로 방문 인증이 되지 않음.
- 음식점/메뉴 DB 조회→Gemini 구조화 응답 대역→검증된 ID/근거의 카드. 4인 세트 52,000원·1인당 13,000원 계산, 오래된 가격 제외, 없는 음식점 ID 거부와 트랜잭션 롤백.
- 이전 조건과 메시지가 후속 요청에 전달됨, 기본 주소와 취향 예산 반영, 추천 후 방문 기록이 증가하지 않음, 대화 삭제 시 메시지·검색 기록도 삭제.
- 영업시간 누락 시 확인 필요, 명시된 휴무·브레이크타임·자정 넘김, 노원구 밖 장소 제외, 역명이 주소에 없더라도 실제 공급자 검색 결과 유지.
- UI의 로그인 설정 오류, 인증 화면 가드, 후기 저장 후 상세 이동, 타인 글 편집 거부, 프로필 Redux 갱신, 비공개 주소 API, 한글 조합 중 Enter 및 중복 제출 방지, 위치 거부 후 직접 출발지 입력.
- 새 조건에 추천 결과가 없으면 이전 조건의 카드를 지움. 다음 추천 로딩 중일 때만 이전 카드를 안내 문구와 함께 표시.

## 실서비스 확인에 남은 항목

운영할 MySQL 연결 정보, 카카오 앱과 Redirect URI, Gemini 키/모델을 설정한 뒤 실제 계정으로 브라우저의 로그인·조건 추출/후속 대화·추천을 확인해야 합니다. 그 결과는 모의 외부 API 테스트 통과와 구분합니다. 실제 음식점은 이용 권한이 확보된 데이터 등록 또는 카카오 로컬 사용 조건 확인이 필요합니다. 실시간 영업/대기·외부 리뷰·결제/재방문·방문 인증은 제공처 연결 전까지 미연동 상태입니다.

MySQL의 상세 검증 항목과 재실행 방법은 [MySQL 검증 기록](mysql-verification.md)에 정리했습니다.
